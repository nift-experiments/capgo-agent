## Complexity removed and retained

The 103 original non-entry JavaScript files have no references in rendered HTML/text assets or independently rebuilt browser modules. `evidence/runtime/retired-assets-audit.json` records the root inventory/digest and every decision. Their immutable golden copies remain reference evidence, but preparation skips them, the pre-build hook removes stale output copies, and parity rejects shipping them again. All 21 entry URLs are rebuilt from source; original URL names remain HTML compatibility identities.

Unused normal-build MDX, remark-gfm, highlight.js and npm semver dependencies were removed. The ordinary Agent wrapper no longer has a dormant MDX-preparation branch. The old importer and questionnaire extraction scripts are historical migration tools, not build prerequisites; they require their optional import/parser dependencies if used independently. They no longer fall back to machine-global absolute module paths. The supported package commands are build, preview, test and audit.

Production CSS, fonts, images and inline vanilla controllers remain deliberately preserved for visual/behavioural parity. The CSS uses original style-scope identities. These identifiers require no Astro runtime. Rewriting all CSS solely to remove those names would add drift without an established maintenance benefit, so no CSS-size improvement is claimed. Historical corpus/prototype records remain as migration provenance and are not read by the normal build; they are not presented as the primary authoring model.

## Actual client code costs

There is no general reduction in client JavaScript: the original production output has 6,073,203 JavaScript bytes; independently generated Agent assets total 6082284 bytes. Astro already compiled most of this site to vanilla browser code. Recovering readable source removes dependency on its build pipeline, not the need for the same browser libraries.

Per-entry import graphs are recorded in the audit. They are uncompressed static bundle sizes, not measured network transfers, and exclude inline scripts, CSS, external providers and service-side responses. Shared chunks must not be summed repeatedly to claim a total page budget.

- Docs search wrapper + static imports: 1644 bytes; including the lazy DocSearch graph: 134776 bytes.
- Mermaid entry + static imports on diagram pages: 716083 bytes; including every reachable lazy diagram/layout library: 5189923 bytes. A specific page does not download every optional layout library.

## Build preparation

The pre-build hook bundles all maintained entry modules with esbuild on every ordinary build. It preserves output mtimes when bytes match and removes outdated generated chunks. Nift hash state and `.nift/native-outputs.json` are ignored, reproducible state. There is no MDX render cache in the ordinary Agent path and no special benchmark-only cache. Final timings will include this hook; the earlier five-controller single 1.98s sample is superseded, not a final claim.

## Compatible own APIs

`runtime/server.mjs` now allowlists original controller endpoints for live-update/builder metrics JSON, credit calculation and signing tools alongside the original adapter contract. It forwards configured provider queries and JSON bodies, validates method/response shape, bounds requests/responses, times out failures, and keeps the optional server token out of client bundles. Snapshot mode never fabricates signing outputs.

To use compatible services:

```sh
CAPGO_API_MODE=live CAPGO_PROVIDER_URL=https://your-compatible-provider.example node runtime/server.mjs
```

For calculator calls through this preview, copy `config/public.example.json` to ignored `config/public.json` and set `PUBLIC_BASE_API_URL` to the preview origin before rebuilding. Registration additionally needs your public Supabase configuration or a compatible public configuration service. Metrics and signing controllers use same-origin original paths. The provider must implement Capgo-compatible response schemas; this adapter is not a replacement for signing infrastructure, device enrollment, authentication or Capgo's private console.

Local tests verify forwarding with test-only JSON fixtures, no-provider 503/setup states, method/route allowlisting and malformed-response rejection. They do not claim to generate valid Apple credentials. Browser private-account/device/signing success remains a production verification limitation.
