# Runtime feature contract

Generation and API behavior are separate. Frozen mode uses hash-recorded public plans/credits snapshots and labels their acquisition date. Live mode uses CAPGO_PROVIDER_URL with CAPGO_PROVIDER_TOKEN only in the local/hosted server. Browser requests same-origin /api endpoints; arbitrary URLs and client-supplied authentication targets are not proxyable. A user-owned provider implements the checked capability contract, independently of Capgo's backend.

Plans/credits feed pricing/calculators. Metrics and rankings require configured provider or explicitly acquired snapshot; missing capability is unavailable/setup, not invented data. Contact POST requires a provider, validates input, and returns genuine provider success/error. Registration/auth remain configured/external links; this does not implement the private console. Device UDID extraction and certificates require a trusted deployed workflow and are documented external services; local tools may offer useful explanatory/validation functions without claiming device identity. Public MCP/discovery is local content/search with CLI instructions; no remote account-control claim. English corpus is included; translation is configurable later, not fabricated.

Vanilla client controls preserve keyboard/no-JS fallback. Server sends explicit status codes, timeouts and bounded bodies. No credentials enter generated output, search or benchmark snapshots. Development fixture provider supplies documented response schemas for successful/error contract tests. Optional Pages preview serves frozen content only; full runtime deployment uses the server recipe.
