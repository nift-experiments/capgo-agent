Basics

What is an iOS signing certificate?

Apple requires every iOS app to be code signed. A signing certificate proves the build comes from a member of your Apple Developer team, and iOS refuses to install or launch apps whose signature it cannot trust.

Getting one takes three files. The CSR (.csr) holds your public key and identity and goes to Apple. The private key (.pem) stays with you. The certificate (.cer) is what Apple issues back. Build tools then need the certificate and private key together as a .p12 file.

On a Mac, Keychain Access creates the CSR and hides the private key in your login keychain. This generator gives you both files directly, so you can create an Apple Distribution or Apple Development certificate from Windows, Linux, or a CI runner, and you always know where the key is.

Security and privacy

How your private key is handled

  • The CSR and RSA 2048-bit private key are created on demand by a stateless Capgo endpoint over HTTPS and returned directly to your browser.
  • Responses are sent with Cache-Control: no-store. Nothing is saved to a database or kept after the response.
  • The CSR is signed with SHA-256, the format Apple Developer expects. Only the CSR is uploaded to Apple; the private key stays with you.
  • The .cer to .p12 converter runs entirely in your browser. Your certificate, private key, and password are never uploaded.
  • No account or sign-up is required, and requests are rate limited to prevent abuse.

Step by step

How to create an iOS distribution certificate without a Mac

From CSR to a signed build on TestFlight. Every step works from a browser and a terminal on Windows, Linux, or macOS.

  1. Step 1

    Generate the CSR and private key

    Enter your name, email, and two-letter country code in the form above and select Generate CSR and private key. Download both files and keep the private key safe.

  2. Step 2

    Create the certificate in Apple Developer

    Sign in to developer.apple.com, open Certificates, Identifiers & Profiles, select the plus button, and choose Apple Distribution or Apple Development.

  3. Step 3

    Upload the CSR and download the .cer

    Upload the ios-certificate-request.csr file, continue, and download the issued certificate, usually named distribution.cer or development.cer.

  4. Step 4

    Convert the .cer to a .p12 file

    Use the .cer to .p12 converter in step 2 of this page: select the .cer and the private key, set a password, and download the .p12. It runs in your browser, or use the OpenSSL command instead.

  5. Step 5

    Create a provisioning profile

    In Apple Developer, create an App Store, ad hoc, or development provisioning profile for your App ID and select the new certificate.

  6. Step 6

    Sign and ship your app

    Import the .p12 and profile into Xcode, fastlane, your CI secrets, or Capgo Cloud Build, then build and upload your app to TestFlight or the App Store.

Troubleshooting

Common iOS certificate errors and fixes

The password you entered is incorrect (Keychain import)
OpenSSL 3 encrypts .p12 files with algorithms that macOS Keychain can reject. Re-export the .p12 with OpenSSL 3 and the -legacy flag shown above.
No certificate matches private key
The .cer was issued for a different CSR. Use the private key downloaded with that exact CSR, or revoke the certificate and start again with a new CSR.
unable to load certificates
Apple delivers .cer files in DER format. Add -inform DER when converting the .cer with openssl x509.
Provisioning profile does not include signing certificate
Profiles are tied to specific certificates. Edit or regenerate the provisioning profile after creating the new certificate, then download it again.
You have reached the maximum number of certificates
Apple limits how many distribution certificates a team can hold. Revoke an unused one in Apple Developer. Live App Store apps are not affected.
Certificate is not trusted in Keychain
Install the current Apple Worldwide Developer Relations (WWDR) intermediate certificate from Apple PKI, then import the .p12 again.

FAQ

iOS certificate generator FAQ

Answers about CSRs, certificate types, .p12 conversion, Apple Developer accounts, and signing iOS apps without a Mac.

What does this iOS certificate generator create?

It creates a Certificate Signing Request (.csr) and the matching RSA 2048-bit private key (.pem). Upload the CSR to Apple Developer to get your Apple Distribution or Apple Development certificate (.cer), then combine the .cer with the private key into a .p12 file for Xcode, fastlane, CI, or Capgo Cloud Build.

What is a Certificate Signing Request (CSR)?

A CSR is a small file that contains your public key and identity details (name, email, country), signed with your private key. Apple uses it to issue a signing certificate bound to that key. The private key never goes to Apple, which is why you must keep the .pem file this tool gives you.

Can I create an iOS distribution certificate without a Mac?

Yes. Generate the CSR and private key here, upload the CSR in the Apple Developer portal from any browser, download the .cer, and convert it to .p12 with the converter in step 2 of this page. Everything works from Windows, Linux, or macOS, so Keychain Access is not required at any step.

Which certificate type should I choose in Apple Developer?

Choose Apple Development to run builds on registered test devices from Xcode. Choose Apple Distribution to sign builds for the App Store, TestFlight, and ad hoc distribution. The same CSR works for either type; the type is selected in Apple Developer, not in this tool.

Is the private key stored on the server?

No. In step 1, the CSR and private key are generated on demand by a stateless Capgo endpoint over HTTPS and returned straight to your browser with Cache-Control: no-store; they are never written to a database or kept after the response. Step 2, the .cer to .p12 converter, runs entirely in your browser and uploads nothing. If your policy requires local key generation, use the equivalent OpenSSL command on this page.

Why do I need to convert the .cer file to .p12?

The .cer file Apple gives you only contains the public certificate. Signing an app also requires the private key, so build tools expect a .p12 file that bundles the certificate and private key behind a password.

How do I convert a .cer to .p12?

Use step 2 on this page: select the .cer from Apple (DER or PEM), select the private key .pem used to create the CSR, enter a password, and select Build .p12 file. The browser checks that the certificate matches the key and builds a 3DES-encrypted .p12 that macOS Keychain, Xcode, and fastlane accept. Nothing is uploaded. You can also copy the .p12 as base64 for CI secrets.

Do I need an Apple Developer account?

Yes. Uploading a CSR and issuing signing certificates requires a paid Apple Developer Program membership (99 USD per year, or the Enterprise program for in-house distribution). The CSR itself can be generated without an account.

How long is an iOS signing certificate valid?

Apple Development and Apple Distribution certificates are valid for one year. Apps already live on the App Store keep working after the certificate expires or is revoked, but you need a new certificate and provisioning profile to sign the next build.

Can I reuse the same CSR or private key?

You can, but a fresh key pair per certificate is safer and easier to rotate. What you must not do is mix them: a .cer only works with the exact private key that created its CSR. If the key is lost, revoke the certificate and generate a new CSR.

Can I use this CSR for push notification (APNs) certificates?

Yes. Apple asks for a CSR when you create an APNs SSL certificate too. For new apps, an APNs authentication key (.p8) is usually simpler because it never expires and works for all your apps.
