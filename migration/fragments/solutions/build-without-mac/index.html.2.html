The Problem

Xcode only runs on macOS

No Mac, no iOS build

Apple's build tools need macOS. A developer on Windows or Linux cannot compile or sign an iOS build on their own machine.

Signing lives on one laptop

Certificates and profiles often sit on one person's Mac. When that person is away or a profile expires, the release waits.

Self-hosted macOS CI is its own project

A rented macOS runner still needs Xcode updates, Fastlane lanes, signing secrets, and debugging when Apple changes something.

The hidden work

What a release build needs besides a Mac

Buying a Mac only solves the hardware part. You still need Apple account setup, signing files, and build tooling that someone keeps working.

1

Apple account setup

An Apple Developer account with admin rights, a bundle ID, an App Store Connect app record, and an API key for uploads.

2

Signing files and profiles

A distribution certificate exported as a .p12, a provisioning profile for each bundle ID, and renewals when they expire.

3

Build tooling

The right Xcode version, CocoaPods or Swift Package Manager, Fastlane, and a place to keep secrets for CI.

How it works

How Windows and Linux developers ship iOS with Capgo

You need a Capacitor app, a Capgo account, and an Apple Developer account. Every command below is from the Capgo CLI docs.

  1. 1

    Set up iOS signing once

    The onboarding reads your Capacitor project, creates the distribution certificate and provisioning profile, and saves them on your machine.

    npx @capgo/cli@latest build init --platform ios
    iOS build guide
  2. 2

    Or save signing files you already have

    If your team already has a certificate and profile, save them with your App Store Connect API key. They stay in a local credentials file.

    npx @capgo/cli@latest build credentials save --platform ios \
  --apple-team-id YOUR_TEAM_ID \
  --apple-key ./AuthKey_XXXXX.p8 \
  --apple-key-id YOUR_KEY_ID \
  --apple-issuer-id YOUR_ISSUER_ID \
  --certificate ./certificate.p12 \
  --ios-provisioning-profile ./profile.mobileprovision
    Managing credentials
  3. 3

    Request the build

    Sync your web build into the iOS project, then request the build. Logs stream to your terminal, and the signed build uploads to App Store Connect for TestFlight.

    npx cap sync ios
npx @capgo/cli@latest build request com.example.app --platform ios
    First build guide
  4. 4

    Run the same command in CI

    Export your saved credentials as CI secrets with build credentials manage, set CAPGO_TOKEN, and run build request in GitHub Actions, GitLab CI, or any runner.

    npx @capgo/cli@latest build credentials manage
# in your CI job
npx @capgo/cli@latest build request com.example.app --platform ios
    GitHub Actions setup

Trust model

Use cloud hardware without handing over your code and keys

Credentials stay on your machine or in your CI secrets. Capgo only holds them while a build runs.

Only the native project is uploaded

The CLI uploads the native platform folder and native dependencies. Your full repository stays on your machine.

Logs stream to your terminal

Build logs stream live while the build runs and are not stored on Capgo servers.

Credentials exist only during the build

Certificates and profiles are used in memory during the build and deleted when it finishes. Each build runs in an isolated environment that is destroyed afterwards.

FAQ

Questions about building iOS without a Mac

What Windows and Linux developers ask before their first cloud iOS build.

Do I need a Mac at any point?

Not to compile, sign, or upload. Builds run on Capgo's Mac mini M4 machines. You still need an Apple Developer account. On Windows or Linux, you create the App Store Connect API key in your browser, then the CLI handles certificates and profiles.

iOS build guide

How long does an iOS build take?

A typical native build takes 2–3 minutes. Logs stream to your terminal while it runs, so you see errors as they happen.

First build guide

Can the build go straight to TestFlight?

Yes. With an App Store Connect API key in your credentials, the signed build uploads to App Store Connect, where you test it in TestFlight and submit it for App Store review. Add --output-upload if you also want a download link for the IPA.

Build configuration

Where are my certificates stored?

On your machine, in ~/.capgo-credentials/credentials.json by default, or in your CI secrets. They are sent to Capgo only for the duration of a build and deleted afterwards.

Managing credentials

Do I need a new build for every change?

No. Plugin, permission, icon, and Capacitor version changes need a new native build. JavaScript, HTML, CSS, and asset changes can ship as live updates to users who already have the store build.
