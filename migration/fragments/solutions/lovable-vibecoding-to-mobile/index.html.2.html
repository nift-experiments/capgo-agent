The Problem

Lovable builds the app. The stores need more.

The app stops at the browser

A Lovable project is a web app. Store listings, push notifications, and device features need a native shell around it.

Lovable cannot run native tooling

Signing, Xcode, Android Studio, and store uploads happen outside Lovable. You need a repo and a build service.

Every change waits on review

After the first store release, each new version goes back through store review, often 24–48 hours, sometimes much longer.

The stack

What each tool does

Lovable builds the web app

Screens, flows, copy, and backend wiring, iterated with prompts. A single-page app gives you a static dist folder to wrap.

Capacitor wraps it

GitHub holds the code. Capacitor puts the built web app into native iOS and Android projects with your app ID, icons, and permissions.

Capgo builds and updates it

Capgo Build creates signed binaries and uploads them to the stores. Live updates ship later web changes to installed apps.

How it works

How Lovable builders ship mobile apps with Capgo

From a Lovable project to store builds and live updates. You run these commands on your computer or let a coding agent run them.

  1. 1

    Export to GitHub and clone

    In Lovable, connect GitHub. Clone the repo and check that the build creates a dist folder with index.html.

    git clone https://github.com/you/your-lovable-app.git
cd your-lovable-app
npm install
npm run build
    Lovable to Capacitor tutorial
  2. 2

    Add Capacitor and Capgo

    Add the native projects, then run the Capgo onboarding. It adds your app, creates a production channel, and installs the updater plugin.

    npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
npx cap init "Your App" com.company.app --web-dir dist
npx cap add ios && npx cap add android
npx @capgo/cli@latest init
    CLI onboarding guide
  3. 3

    Build signed apps in the cloud

    Set up signing once, then request iOS and Android builds. Signed builds upload to App Store Connect and Google Play for review.

    npx @capgo/cli@latest build init
npx @capgo/cli@latest build request --platform ios
npx @capgo/cli@latest build request --platform android
    Capgo Build docs
  4. 4

    Ship each Publish as a live update

    Add CAPGO_TOKEN as a GitHub secret and a workflow that builds and uploads on push. New plugins or permissions still need a new store build.

    # step in .github/workflows, with CAPGO_TOKEN from secrets
npm ci && npm run build
npx @capgo/cli@latest bundle upload --channel=production --auto-bump
    Lovable Publish to live update guide

Let your coding agent do the setup

Lovable cannot run the Capgo CLI. After you clone the repo, paste this into a local coding agent such as Claude Code, Codex, or Cursor. It installs the Capgo MCP server, adds Capacitor and the updater, and leaves TODOs for signing instead of inventing secrets.

Prompt for your coding agent

I want this project, exported from Lovable, to become a Capacitor mobile app using Capgo from the start.

Set up the project so an AI agent can use Capgo's MCP release tools through install-mcp:

1. Install the Capgo CLI MCP server for the active AI client. For Codex, run:
   - npx @capgo/cli@latest login
   - npx install-mcp 'npx @capgo/cli@latest mcp' --client codex
   Replace codex with cursor, claude-code, gemini-cli, or windsurf if that is the client this project uses.
2. Read Capgo's public MCP metadata when tool details are needed:
   - https://capgo.app/.well-known/mcp/server-card.json
   - https://capgo.app/.well-known/agent-skills/capgo-cli-mcp/SKILL.md
   If this client supports agent skills, also run: npx skills add Cap-go/capgo-skills
3. Add a short docs/agent-mobile-release.md file that tells the agent to use the Capgo CLI MCP server as a local stdio server, not a remote HTTP endpoint.
4. Add Capacitor for iOS and Android using the package manager already used by this project.
5. Configure capacitor.config.ts with:
   - appName: the current Lovable app name
   - appId: a production-style bundle ID I can edit later, such as com.company.app
   - webDir: the production build output folder
   - plugins.CapacitorUpdater.defaultChannel: production
6. Install and configure @capgo/capacitor-updater.
7. Add package scripts for:
   - building the web app
   - syncing Capacitor
   - uploading a production Capgo bundle
   - starting Capgo Build setup for iOS
   - requesting an iOS cloud build
8. Create a first production channel plan:
   - production for users
   - preview for stakeholder review
   - staging for internal testing
9. Keep normal docs and README commands copy-pasteable with npm/npx unless this project already uses another package manager. Keep the Capgo MCP install command exactly as shown above.
10. Do not fake native signing credentials. Leave clear TODOs for the Capgo API key, Apple team details, and bundle ID.
11. After making changes, summarize exactly what changed and what command I should run next.

FAQ

Questions Lovable builders ask

Short answers for taking a Lovable or vibe-coded app to the App Store and Google Play.

Can Lovable publish straight to the App Store?

No. Lovable builds the web app. You export it to GitHub, wrap it with Capacitor, and build signed iOS and Android apps with Capgo Build, which uploads them to App Store Connect and Google Play.

Lovable to Capacitor tutorial

Do I need a Mac or Xcode?

No. Capgo Build runs iOS builds on cloud Mac machines. You still need an Apple Developer account for the App Store and a Google Play developer account for Android.

Capgo Build docs

Will changes I make in Lovable reach the mobile app?

Yes, for web-layer changes. With GitHub sync on, Publish pushes a commit, a GitHub Action runs bundle upload, and installed apps download the update. New plugins or permissions still need a new store build.

Lovable Publish to live update guide

My Lovable project uses Next.js. Does it work?

Yes, with a static export. Point Capacitor's webDir at the out folder instead of dist. Vite single-page apps work as they are.

Next.js with Capacitor

Can my AI agent handle the release steps?

Yes. npx @capgo/cli mcp starts a local MCP server that Claude Code, Codex, or Cursor can use to upload bundles, manage channels, and request builds. Capgo skills add Capgo-specific instructions for the agent.
