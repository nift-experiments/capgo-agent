How it works

How web teams ship mobile apps with Capgo

From an existing web app to store builds and live updates. Capacitor commands come from the Capacitor CLI, Capgo commands from the Capgo CLI docs.

  1. 1

    Add Capacitor to your web app

    Install Capacitor, set the app name, bundle ID, and build output folder, then add the iOS and Android projects.

    npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
npx cap init "Your App" com.company.app --web-dir dist
npx cap add ios
npx cap add android
    Web app to Capacitor guide
  2. 2

    Connect the app to Capgo

    The onboarding adds your app to Capgo, creates a production channel, installs the updater plugin, and walks you through a first test update.

    npx @capgo/cli@latest init
    CLI onboarding guide
  3. 3

    Build signed apps in the cloud

    Set up signing once, then request iOS and Android builds. Signed builds upload to App Store Connect and Google Play for review.

    npm run build && npx cap sync
npx @capgo/cli@latest build init
npx @capgo/cli@latest build request --platform ios
npx @capgo/cli@latest build request --platform android
    Capgo Build docs
  4. 4

    Ship web changes as live updates

    After users install the store app, upload each new web build to a channel. Native changes still need a new store build.

    npm run build
npx @capgo/cli@latest bundle upload --channel production
    Ship an update

Give your coding agent a mobile-release brief

If you use an AI coding agent, paste this brief. It inspects the app and writes a handoff file with the config, plugin needs, and open tasks before anyone runs native tooling.

AI mobile-release brief

You are preparing this existing web app to become an installable iOS and Android app.
Do not assume you can run local tooling. If this environment cannot create native projects or run local tools, create a clean handoff document instead.

Inspect the app and return:

1. The framework, package manager, production build process, and build output folder.
2. Whether the app can be exported or committed to a real Git repository.
3. The app name, bundle ID or package ID suggestion, app icon and splash-screen source, and any missing brand assets.
4. Auth, redirect, deep-link, storage, camera, push, payment, geolocation, file, or notification features that need native plugin planning.
5. Routing, environment variables, API URLs, and asset assumptions that could break inside a native WebView.
6. A proposed Capacitor configuration, including appId, appName, webDir, and required plugins, without inventing secrets.
7. A release-channel plan: production, staging, preview, and rollback expectations for web-layer updates.
8. A list of tasks that must happen outside this environment, such as Apple signing, Android keystore setup, native sync, store records, and signed builds.
9. A docs/mobile-release-handoff.md file with the exact checklist, open questions, and files that a developer or build service should handle next.
10. A short summary of what you changed, what you could not do in this environment, and the next human action.

FAQ

Questions web teams ask

Short answers for teams taking an existing web app to the App Store and Google Play.

Do we have to rewrite our web app?

No. Capacitor runs your existing web build inside native iOS and Android projects. You add plugins where you need device features and keep one codebase for web and mobile.

Web app to Capacitor guide

Does it work with Next.js?

Yes, with a static export. Capacitor loads files from your build output folder, so set output: 'export' and point webDir at the exported folder. Vite, Angular, and Vue produce static output by default.

Next.js with Capacitor

Do we need a Mac for the iOS build?

No. Capgo Build runs iOS builds on cloud Mac machines and uploads the signed build to App Store Connect. You still need an Apple Developer account.

Capgo Build docs

What can we change without a store release?

JavaScript, HTML, CSS, and assets can ship as live updates. Adding a plugin, changing permissions, or updating Capacitor needs a new store build.

Live update or native build?

Can mobile updates ship from our existing CI?

Yes. Run bundle upload after your web build in GitHub Actions, GitLab CI, or any pipeline, and request native builds from the same pipeline when native code changes.
