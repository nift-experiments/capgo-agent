Set a native version floor on every bundle

Block updates across semver lines

--disable-auto-update major, minor, or patch keeps a device from receiving a bundle outside its native version line. These rules compare version numbers only. They do not inspect native code.

How it works

How teams with several native versions ship with Capgo

A CI setup that lets the live update lane and the store lane work side by side. Every command below is from the Capgo CLI docs.

  1. 1

    Ask whether the commit needs a native build

    build needed compares your native packages with the channel. It prints yes and exits with code 1 when a store release is required, and no when a live update is enough.

    npx @capgo/cli@latest build needed com.example.app --channel production
    build needed reference
  2. 2

    Switch the channel to the metadata strategy

    Do this once. From then on, each bundle carries a minimum native version and devices below it skip the bundle.

    npx @capgo/cli@latest channel set production com.example.app \
  --disable-auto-update metadata
    Version targeting docs
  3. 3

    Upload everyday live updates

    Keep --auto-min-update-version on every upload. --fail-on-incompatible stops the job if the bundle needs native code the channel does not have.

    npx @capgo/cli@latest bundle upload --channel production \
  --auto-min-update-version \
  --fail-on-incompatible
    Native compatibility docs
  4. 4

    Upload the bundle for a new native release

    When the new binary ships, upload its bundle without --fail-on-incompatible. Capgo raises the floor so older builds skip it, and later checks compare against the new native packages.

    npx @capgo/cli@latest bundle upload --channel production \
  --auto-min-update-version

Appflow migration

Coming from Ionic Appflow?

Appflow matched live updates to native versions for you. In Capgo you get the same result with channels and version rules:

  1. 1 Create a channel for each native line, for example v1 and v2.
  2. 2 Set defaultChannel in each native build's Capacitor config to its channel.
  3. 3 Upload each bundle to the channel of the native line it was built for.
  4. 4 Keep --auto-min-update-version on uploads so a bundle that needs newer native code skips older builds.

Channel per native line 
// capacitor.config.ts in your 2.x native builds
plugins: {
  CapacitorUpdater: {
    defaultChannel: 'v2',
  },
},

# ship a fix to 2.x users only
npx @capgo/cli@latest bundle upload --channel v2 \
  --auto-min-update-version

FAQ

Questions about versions in the wild

For teams supporting users who update the store app at different times.

What happens to users who never update the native app?

They keep receiving bundles that are compatible with their native version. With the metadata strategy, a bundle whose minimum native version is above theirs is skipped, and they stay on their current bundle.

Version targeting docs

Is --disable-auto-update major enough to prevent crashes?

No. Version rules only compare version numbers, so a native change shipped in a minor or patch release still goes out. Use --fail-on-incompatible or --auto-min-update-version, which check your native packages.

Native compatibility docs

How does CI know whether a change needs a store release?

Run build needed or bundle releaseType against the channel. Both compare native package metadata. They do not see every edit under ios/, android/, or capacitor.config, so gate those paths in git as well.

Choose OTA or native build in CI

We are moving from Ionic Appflow. Can we keep version-matched updates?

Yes. Use a channel per native line with defaultChannel, or the metadata strategy with --auto-min-update-version. The Appflow migration guide walks through the setup.

Appflow migration guide

What if an incompatible bundle already went out?

Point the channel back to the last compatible bundle from its history, or force the built-in bundle, and ship the native build. notifyAppReady() rolls back a bundle that fails to start, but it is not a substitute for compatible native code.
