Why teams move

The web code is fine. The Cordova layer slows you down.

Most Cordova apps keep their UI and logic. The work is in plugins, native config, and the release process.

Plugins stop getting updates

Many Cordova plugins are no longer maintained. When a new iOS or Android SDK breaks one, your team forks it and carries the patch.

Native projects are generated

Cordova rebuilds platforms/ from config.xml and hooks, so manual native edits are easy to lose. Capacitor keeps real ios/ and android/ projects in your repo that you open in Xcode and Android Studio.

New device features need new plugins

Passkeys, biometrics, in-app purchases, and background location all need a maintained native plugin. On Capacitor you can choose from official plugins and Capgo plugins.

Every fix waits on store review

Without live updates, a one-line JavaScript fix needs a new binary. Store review is often 24–48 hours, sometimes much longer, and users still have to update.

How it works

How Cordova teams move to Capacitor with Capgo

The same four steps apply whether you do it yourself, hand it to an AI agent, or have our team run it.

  1. 1

    List your plugins and native config

    Export your plugin list and platforms. Note config.xml preferences, plugin variables, hooks, and any manual edits in platforms/. This is your migration input.

    cordova plugin list
cordova platform ls
    Step-by-step migration guide
  2. 2

    Add Capacitor next to your web build

    Install Capacitor, set webDir to your build output folder, and add the iOS and Android projects. Your built web app is copied into both.

    bun add @capacitor/core @capacitor/cli
bun add @capacitor/ios @capacitor/android
bunx cap init
bunx cap add ios
bunx cap add android
  3. 3

    Replace your Cordova plugins

    Map each plugin to an official Capacitor plugin or a Capgo plugin. Capacitor can run many Cordova plugins, but maintained replacements are safer for login, payments, and storage.

    bun add @capgo/capacitor-native-biometric
bun add @capgo/capacitor-social-login
bunx cap sync
    Browse Capgo plugins
  4. 4

    Build, release, then update live

    Build and sign with Capgo Build and ship a store update with the same app ID, so it installs over the Cordova version. After that, ship web-layer fixes as live updates.

    npx @capgo/cli@latest build init
npx @capgo/cli@latest build request --platform ios
# after the store release, for web-layer fixes
npx @capgo/cli@latest bundle upload --channel production

FAQ

Cordova to Capacitor questions

What teams ask before they start a migration.

Do we have to rewrite the app?

No. Your UI and business logic stay. The work is in the native projects, plugins, config, and build setup. Most code changes are in the places where you call a plugin API.

Step-by-step migration guide

Can we keep our Cordova plugins?

Capacitor can run many Cordova plugins, so you can keep some while you migrate. For login, payments, storage, and other critical paths, use a maintained Capacitor plugin. Capgo plugins are free under MPL-2.0.

Browse Capgo plugins

Can we use Capgo live updates before we migrate?

Yes. @capgo/cordova-updater supports Cordova iOS 7+ and Android 13+ with the same CLI and channels. When you move to Capacitor, keep the Capgo app ID and channels and switch to @capgo/capacitor-updater.

Cordova updater guide

How long does a migration take?

It depends on how many plugins you use and how much custom native code you have. If our team runs it, you get a fixed-price proposal with scope and timeline after a free discovery call.

Migration consulting

What can we ship as a live update after the migration?

Changes to JavaScript, HTML, CSS, and assets. Adding or upgrading a native plugin needs a new store build. When you upload a bundle, Capgo checks native compatibility against the bundle live on the channel.
