How it works

How IT teams keep managed devices current with Capgo

Configure the app once, then release from CI and watch from the console. Every command and setting below is from the Capgo docs.

  1. 1

    Install the app once with a default channel

    defaultChannel puts every device from this build on the right channel, for example one per site. autoUpdate: 'always' applies a new bundle as soon as it downloads, which suits kiosk apps that never go to the background.

    // capacitor.config.ts
plugins: {
  CapacitorUpdater: {
    defaultChannel: 'site-eu',
    autoUpdate: 'always',
    autoSplashscreen: true,
  },
},
    Update behavior docs
  2. 2

    Call notifyAppReady() at startup

    This tells the updater the new bundle loaded. If a bundle never gets there, the device returns to the last working one by itself.

    import { CapacitorUpdater } from '@capgo/capacitor-updater'

// once your app has loaded
CapacitorUpdater.notifyAppReady()
    notifyAppReady() and automatic rollback
  3. 3

    Publish from CI, one site first

    Upload with --delta so devices download only changed files. When the first site looks right, link the same bundle to the other channels.

    npx @capgo/cli@latest bundle upload --channel site-eu --delta
# after the first site checks out
npx @capgo/cli@latest channel set site-us com.example.app \
  --bundle 1.4.2
    Channels docs
  4. 4

    Watch devices and roll back from one place

    Device logs show each check, download, install, and failure. Observe (beta) compares launch and WebView timing by bundle version. To roll a site back, link its previous bundle.

    # roll site-eu back to the previous bundle
npx @capgo/cli@latest channel set site-eu com.example.app \
  --bundle 1.4.1

What this is, and what it is not

  • Use this for private enterprise distribution through MDM, Apple Business Manager, Android Enterprise, or an internal enterprise store.
  • Capgo updates JavaScript, HTML, CSS, and assets. Native plugin changes still require a new signed native package.
  • Offline devices keep running the last successful bundle until they reconnect and fetch the next approved update.
  • This is not a consumer App Store bypass. It is a private-app operating model for teams that already self-distribute.

FAQ

Questions from teams running managed devices

For kiosk, MDM, and internal apps where nobody updates by hand.

Our kiosk app never goes to the background. Will it still update?

Yes, with autoUpdate set to 'always'. The plugin checks every 10 minutes while the app is open (periodCheckDelay, 600 seconds minimum) and applies a downloaded bundle right away. With the default 'atBackground', the bundle waits until the app is backgrounded. Instant apply also needs @capacitor/splash-screen with autoSplashscreen turned on.

Update behavior docs

What happens if an update breaks the app on a device?

If the new bundle does not call notifyAppReady() within 10 seconds, the device goes back to the previous working bundle. You can also point the channel back to an earlier bundle, or force the built-in bundle, and devices pick it up on their next check.

Rollbacks docs

Can we push a fix before the next update check?

With Capgo Notifications set up, channel set --send-update-notification sends a silent update-check notification after you change the channel's bundle. Delivery is best effort and depends on the operating system, network, and device state. It cannot reach offline or force-quit apps.

Silent update checks

Do we still need MDM or an internal store?

Yes, for the native app. Capgo updates JavaScript, HTML, CSS, and assets. New plugins, native code, and Capacitor config changes still ship as a new signed package through your MDM or internal store.

What needs a native build

Can update traffic stay on our own infrastructure?

The Enterprise plan offers dedicated, hybrid, and licensed self-hosted setups. You can also run your own update server with the open-source updater, but then you build features such as channels and statistics yourself.
